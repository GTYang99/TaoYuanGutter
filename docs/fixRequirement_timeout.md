# Fix Requirement Timeout

## 問題背景

目前 `/v1/ditch/storeDitch` 發生逾時時，系統會走專用的網路逾時提示流程，並在使用者按下 `關閉` 後執行既定收尾。

但若 `/v1/ditch/storeDitch` 回傳 `409 Conflict`，目前尚未定義一條專屬且清楚的提示流程，用來表達：

- 請求可能已送出
- 但本次上傳的側溝照片已被認領
- 使用者需要稍後確認是否已成功上傳，或重新嘗試

## 修正目標

當 `/v1/ditch/storeDitch` 回傳 `409` 時，應視為一種特殊錯誤情境，顯示單一關閉按鈕的提示視窗，而不是走一般上傳失敗雙按鈕流程。

## 指定顯示內容

### 視窗標題

`照片認領失敗`

### 視窗說明

`已送出上傳請求，但本次上傳側溝照片已被認領。請稍後確認是否已上傳成功，或重新嘗試。`

### 按鈕

僅提供一個按鈕：

- `關閉`

不得提供：

- `重傳`
- `存入草稿`
- 其他附加選項

## 新增模式與編輯模式要求

新增模式與編輯模式必須保持一致：

1. 只要 `/v1/ditch/storeDitch` 回傳 `409`
2. 都必須顯示相同的 `照片認領失敗` 視窗
3. 都必須使用相同的單一 `關閉` 行為

## 關閉後的收尾要求

按下 `關閉` 後，收尾流程必須與目前 `storeDitch timeout` 一致。

也就是說：

1. 視為本次請求未完成確認
2. 呼叫與 `storeDitch timeout` 相同的 host 收尾流程
3. 後續收尾必須等同於目前 `onStoreDitchNetworkClosed(...)` 這條路

## 本次需求重點

本次修正重點在於：

1. `/v1/ditch/storeDitch` 回 `409` 時，增加一條專屬提示分支
2. 使用者體驗應類似 timeout 類型視窗
3. 關閉後行為要與 `storeDitch timeout` 相同
4. 新增模式與編輯模式一致

## 測試接口

本次修正需要保留一個開發測試入口，並由 `ENABLE_GROUP_SIMULATION = true` 控制是否顯示。

### 入口方式

- 在新增或編輯側溝表單中，長按 `送出` 按鈕
- 若 `ENABLE_GROUP_SIMULATION = true`，會顯示模擬選單
- 若 `ENABLE_GROUP_SIMULATION = false`，不應顯示任何測試入口

### 模擬項目

測試選單至少應提供：

1. `模擬網路逾時`
2. `模擬照片認領失敗(409)`

## 不在本次修正範圍

本次不要求變更以下內容：

1. `/v1/ditch/storeDitch` API 本身
2. 照片上傳 API 結構
3. 草稿資料結構
4. `PhotoSlotUploadCoordinator`
5. 一般 `storeDitch` 失敗的既有分支邏輯（除 `409` 特例外）
