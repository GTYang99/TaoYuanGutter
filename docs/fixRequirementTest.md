# Fix Requirement Test

## 測試目標

驗證 `AddGutterBottomSheet` 在送出前的照片判定順序正確：

- 有可用照片路徑但缺少 `img_id` 時，先走補傳流程
- 路徑存在但檔案不可用時，視為缺少照片
- 只有真正無法補傳或資料不足時，才出現 `資料/照片不足` Alert

## 驗收條件

### 1. 可補傳照片不應被 Alert 擋住

前置條件：

- 某個必要照片欄位有可用照片路徑
- 該欄位沒有 `img_id`
- 照片檔案本身可讀且存在

預期結果：

- 送出前先進入一併補傳照片流程
- 系統應嘗試補齊缺少的 `img_id`
- 不應直接跳出 `資料/照片不足` Alert

### 2. 已有 `img_id` 的照片應視為完成

前置條件：

- 照片欄位同時具有可用照片路徑與 `img_id`

預期結果：

- 該照片視為已完成
- 不會重複補傳
- 不應觸發照片不足 Alert

### 3. 沒有照片路徑且沒有 `img_id`

前置條件：

- 必要照片欄位沒有可用照片路徑
- 也沒有 `img_id`

預期結果：

- 視為缺少照片
- 應顯示 `資料/照片不足` Alert
- 提示使用者補拍

### 4. 有路徑但檔案不可用

前置條件：

- 必要照片欄位有路徑
- 但檔案實際不存在、損毀或不可讀

預期結果：

- 視為缺少照片
- 不應誤判為可補傳成功
- 最後應進入 `資料/照片不足` Alert

## 測試情境

### A. 正常補傳

1. 開啟新增側溝表單
2. 填入必要資料
3. 為必要照片欄位提供可讀的本機照片路徑，但不先建立 `img_id`
4. 送出

預期：

- 先補傳照片
- 補到 `img_id` 後繼續送出

### B. 既有完成照片

1. 開啟新增或編輯表單
2. 確認必要照片欄位同時存在照片路徑與 `img_id`
3. 送出

預期：

- 不進入補傳
- 不出現照片不足 Alert

### C. 缺少照片

1. 開啟表單
2. 保留必要資料完整
3. 將必要照片欄位清空
4. 送出

預期：

- 顯示 `資料/照片不足` Alert
- 阻擋送出

### D. 路徑損壞

1. 開啟表單
2. 在必要照片欄位填入失效路徑
3. 不提供 `img_id`
4. 送出

預期：

- 視為缺少照片
- 最後進入 `資料/照片不足` Alert

## 需要檢查的點

- 驗證流程是否先檢查資料欄位，再檢查照片可用性
- 是否能正確分辨「有路徑但缺 `img_id`」與「完全沒有可用照片」
- 補傳流程是否真的會在送出前啟動
- Alert 是否只在真正缺照片或缺資料時出現

## 不應修改的範圍

- 單張照片上傳 API 結構
- `PhotoSlotUploadCoordinator` 的上傳機制
- 草稿資料結構
- `img_id` 回填結構
