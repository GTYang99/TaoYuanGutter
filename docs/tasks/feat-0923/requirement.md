# Requirement

## Background

- 待上傳草稿列表目前沒有區分草稿是否曾經送出 `POST /v1/ditch/storeDitch`。
- 使用者需要從列表快速辨識：草稿是從未送出，或已送出但因失敗、逾時等原因仍留在本機。

## Goal

- 在 `PendingDraftsBottomSheet` 的草稿項目顯示「曾提交過上傳」或「未提交上傳」tag。
- 只有真正進入 `storeDitch` 呼叫的草稿才算「曾提交過上傳」；App 在呼叫前閃退或從未呼叫 API 的草稿算「未提交上傳」。
- 由檢視流程進入編輯、可由有效 `SPI_NUM` 識別的既有側溝草稿，顯示唯一 tag「既有側溝編輯中」。

## Functional Requirements

- 在草稿持久化資料保存是否曾提交 `storeDitch` 的狀態，且需涵蓋新增、重試、失敗、逾時及 App 重啟後恢復。
- 新增流程在呼叫 `storeDitch` 前持久化「已提交」狀態；編輯流程在呼叫帶 `SPI_NUM` 的 `storeDitch` 前也持久化相同狀態。
- `PendingDraftsBottomSheet` 的一般草稿依狀態顯示一個 tag：已提交顯示「曾提交過上傳」，未提交顯示「未提交上傳」。
- 「曾提交過上傳」沿用 `AddGutterBottomSheet` 的虛擬點 badge：實心主色背景、白色文字。
- 「未提交上傳」沿用相同尺寸與字體，但不填滿，僅顯示邊框與主色文字。
- 「既有側溝編輯中」沿用「未提交上傳」的透明底、主色邊框與主色文字樣式。
- 草稿若具有效 `SPI_NUM`，tag 判定優先於 `hasSubmittedStoreDitch`，只顯示「既有側溝編輯中」，不得同時顯示「曾提交過上傳」或「未提交上傳」。
- 既有側溝編輯草稿仍維持原有可編輯與重新送出流程，不套用一般已提交草稿的唯讀／重新上傳限制。
- 成功上傳後既有草稿刪除行為維持不變；未提交 tag 不得影響既有編輯、刪除或重試流程。
- 已提交的一般草稿恢復後，表單內容全部鎖定：基本欄位、節點、座標、照片、附件、類型、虛擬點與匯入操作均不可修改。
- 已提交草稿恢復後，表單只允許返回或按「重新上傳」；重新上傳使用原始完整草稿內容與既有 `storeDitch` 流程。
- 唯讀表單的半透明遮罩覆蓋所有可編輯表單區域，但不遮住返回與「重新上傳」操作；視覺沿用既有 disabled／loading overlay 規範。
- 已提交草稿仍可從列表長按刪除；刪除沿用既有確認與本機資料清理流程。
- 重新上傳失敗、逾時或 App 中斷後，草稿仍維持「曾提交過上傳」與唯讀狀態，允許再次整份重新上傳。
- 舊版草稿缺少提交狀態時一律以「未提交上傳」處理，仍可正常編輯。

## Non-functional Requirements

- 既有 Room 草稿資料必須透過 migration 相容；舊版草稿缺少新欄位時不得造成讀取或恢復失敗。
- 不新增第三方依賴，不改變 `storeDitch` API payload 或既有上傳錯誤處理。

## Acceptance Criteria

- AC-001：無有效 `SPI_NUM` 的一般草稿在真正進入新增 `storeDitch` 呼叫前已保存提交狀態；即使之後 API 失敗、逾時或 App 在回呼前結束，重新開啟草稿列表仍顯示「曾提交過上傳」。具有效 `SPI_NUM` 的既有側溝草稿則不受此 tag 狀態影響，固定顯示「既有側溝編輯中」。
- AC-002：無有效 `SPI_NUM` 且未進入 `storeDitch` 呼叫的普通草稿（包含呼叫前 App 閃退而留下的草稿）顯示「未提交上傳」；此狀態在重啟與恢復草稿後仍保留。具有效 `SPI_NUM` 的草稿即使尚未進入 API，仍固定顯示「既有側溝編輯中」。
- AC-003：三種 tag 的文字、位置、尺寸與樣式符合指定規則；「曾提交過上傳」為實心主色／白字，「未提交上傳」與「既有側溝編輯中」為透明底／主色邊框／主色字；同一草稿只顯示一個 tag。
- AC-004：具有效 `SPI_NUM` 的檢視／編輯既有側溝草稿只顯示「既有側溝編輯中」，不受 `hasSubmittedStoreDitch` 影響；點擊恢復後仍可修改與重新送出，長按刪除與成功清除行為不回歸。
- AC-005：舊版 Room 草稿可完成 migration、列表載入與恢復；缺少提交狀態時依規劃的相容預設處理，不影響既有草稿資料。
- AC-006：已提交的一般草稿恢復後，基本欄位、節點、座標、照片、附件、類型、虛擬點與匯入操作全部不可修改；半透明遮罩覆蓋可編輯區域，但返回與「重新上傳」可操作。
- AC-007：已提交草稿按「重新上傳」時送出原始完整內容；成功沿用既有草稿刪除／清理，失敗、逾時或中斷保留草稿與已提交狀態，且可再次重新上傳。
- AC-008：既有側溝編輯草稿在尚未進入 `storeDitch`、更新失敗、逾時或 App 中斷後，均保留草稿內容、`SPI_NUM` 與「既有側溝編輯中」tag；恢復後仍可繼續修改並重新送出。

## Constraints

- 僅處理待上傳草稿列表、其恢復表單與提交狀態來源；不修改 API 契約、後端資料或其他列表。
- 必須保留工作區既存的 `gradle/libs.versions.toml` 修改與 `.worktrees/` 未追蹤內容。

## Open Questions

- 無。舊版草稿採 `false`／「未提交上傳」相容預設；有效 `SPI_NUM` 優先顯示「既有側溝編輯中」，維持既有檢視／編輯與重新送出流程；一般已提交草稿仍維持唯讀與整份重新上傳規則。
