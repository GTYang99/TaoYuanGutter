# Requirement

## Background
- 「無法開蓋」目前每次勾選皆要求確認，即使沒有資料可被清除。
- 表單從 `GutterFormActivity` 返回側溝節點列表時，未完成資料會直接存為草稿並返回，沒有完成度提醒。

## Goal
- 僅在「無法開蓋」會清除既有內容時顯示確認。
- 離開新增／編輯表單回到 `AddGutterBottomSheet` 前，以既有送出驗證規則提醒未完成資料，並保留既有草稿保存與返回行為。

## Functional Requirements
- 勾選「無法開蓋」時，檢查所有既有清除欄位與第 2、3 張照片；至少一項有資料才顯示既有確認 Alert。
- 沒有可清除資料時，直接勾選「無法開蓋」並沿用既有清除與必填規則。
- 新增／編輯表單透過系統返回鍵或畫面返回按鈕離開到 `AddGutterBottomSheet` 時，使用既有基本欄位及照片必填驗證規則判斷完整性。
- 未完成時，顯示無標題、內文為「尚未填寫完畢」、單一「確認」按鈕的 Alert；確認後依現有行為儲存草稿並返回。
- 已完成時不顯示該 Alert，依現有行為儲存草稿並返回。
- 檢視→編輯→返回檢視預覽不離開 Activity，維持既有行為且不顯示未完成 Alert。

## Non-functional Requirements
- 不變更草稿資料、照片上傳、既有無法開蓋確認後清除，以及檢視模式導頁行為。

## Acceptance Criteria
- AC-001：無法開蓋的清除欄位和第 2、3 張照片皆無資料時，勾選不顯示確認 Alert，且狀態成功切換。
- AC-002：任一清除欄位或第 2、3 張照片有資料時，勾選顯示既有確認 Alert；確認與取消結果維持既有行為。
- AC-003：新增／編輯表單未通過既有基本欄位或照片驗證時，以系統返回鍵或 `btnBack` 返回，顯示指定單一確認 Alert；確認後草稿保存並返回列表。
- AC-004：新增／編輯表單通過既有驗證時，以系統返回鍵或 `btnBack` 返回，不顯示未完成 Alert，且維持草稿保存與返回列表。
- AC-005：檢視→編輯→返回預覽時不顯示未完成 Alert，且不離開 `GutterFormActivity`。
- AC-006：一般側溝的側溝形式、側溝位置、測量座標編號或溝蓋板厚度未填時，返回顯示「尚未填寫完畢」。
- AC-007：無法開蓋仍要求側溝形式、側溝位置與測量座標編號；明溝僅免填溝蓋板厚度，其餘細節欄位維持必填。

## Constraints
- 完整性定義必須完全沿用既有 `validateRequiredFields()`、虛擬點例外及 `validateAllPhotos()` 規則。
- 未完成 Alert 僅在實際離開 Activity 返回節點列表時觸發。

## Follow-up Decision (2026-09-14)
- 一般側溝須驗證側溝形式、側溝位置、測量座標編號及溝蓋板厚度。
- 無法開蓋維持既有細節欄位與照片 2、3 免填規則；但側溝形式、側溝位置及測量座標編號仍為必填。
- 明溝僅溝蓋板厚度免填；其餘既有細節欄位仍為必填。
