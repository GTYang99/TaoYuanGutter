# Requirement

## Background
- 主地圖的「新增側溝」目前直接開啟單一側溝點位／表單流程，使用者無法在同一次工作階段內先建立並切換多筆側溝。
- 現有草稿是一筆 `GutterSessionDraft` 儲存一整條側溝的所有點位；本工項需讓清單中的每條側溝各自成為一筆可恢復的草稿。

## Goal
- 將新增側溝入口改為「新增側溝清單」底部面板，使用者可新增多筆側溝、選擇其中一筆進入既有表單編輯，並將未上傳的每條側溝獨立保存為草稿。

## Functional Requirements
- 使用者從主地圖點選新增側溝時，先開啟新增側溝清單，而不是直接開啟單一側溝表單。
- 清單提供新增側溝操作；新增後建立一筆可編輯的側溝工作項目，並進入既有側溝編輯流程。使用者返回後回到清單，且可再新增或選擇其他側溝。
- 清單每列依建立順序顯示「側溝草稿 N」、建立時間（精確到秒）及已存節點數；點選列可開啟對應的側溝表單。
- Toolbar 左側為關閉／刪除鍵，右側為「＋新增」鍵。
- 關閉清單且仍有未上傳側溝時，顯示「未上傳側溝草稿將儲存到草稿中」確認 Alert，提供「確定」與「取消」；確定後每條未上傳側溝分別儲存為既有草稿列表中的獨立草稿，取消後保留清單與資料。沒有未上傳項目時直接關閉，不顯示 Alert。
- 每筆側溝的有效修改必須立即持久化，讓 Activity／程序被系統終止或非正常離開後仍可從草稿列表恢復；關閉確認不可成為唯一的儲存時機。
- 單一側溝送出成功後，依既有流程開啟檢視側溝頁面；使用者關閉檢視頁面後返回本次新增側溝清單，並只從該清單與本機未上傳草稿移除已成功上傳的側溝，讓使用者繼續處理其他項目。不得呼叫後端刪除側溝 API。
- 單一側溝送出失敗後，顯示既有失敗 Alert；使用者確認後返回本次新增側溝清單，保留失敗項目供繼續編輯或重送，直到上傳成功或使用者關閉清單。
- 每張實際上傳到 `/v1/node/nodeImage` 的照片維持獨立 multipart 請求，且必須帶該照片的 `captured_at`。沿用現有 app 的照片時間格式；無法解析原始時間時，以裝置目前時間補入。
- `/v1/ditch/storeDitch` 的任何節點均不得送出 `captured_at`；該欄位只屬於各自的照片上傳請求。
- 既有草稿恢復、照片、本機照片清理與上傳流程須維持相容。

## Non-functional Requirements
- 使用現有 Android Kotlin、ViewBinding、BottomSheetDialogFragment、Room 與既有草稿資料模型慣例；不得引入新的 UI 框架。
- 清單遵循 Figma 手機版面板結構：402px 參考寬度、24px 上圓角、70px Toolbar、置中標題、清單列 88px、左右 32px 內距及底部分隔線。

## Acceptance Criteria
- AC-001：從主地圖新增側溝入口進入新增側溝清單，不再直接進入單一側溝表單。
- AC-002：使用者可在清單新增兩筆以上側溝、分別開啟表單編輯，返回後仍能在同一清單中切換各筆資料。
- AC-003：每筆清單列依建立順序顯示「側溝草稿 N」、建立時間至秒及正確的已存節點數，點選後開啟其對應表單。
- AC-004：Toolbar 左側顯示關閉／刪除鍵、右側顯示新增鍵；有未上傳項目時關閉清單顯示指定 Alert，取消會留在清單，確定會將每條未上傳側溝各自儲存為一筆可恢復草稿；沒有未上傳項目時直接關閉且不顯示 Alert。
- AC-005：對任一側溝完成有效修改後，即使未再按關閉且 Activity／程序重建，草稿列表仍可恢復各筆側溝的資料；各草稿互不覆寫。
- AC-006：成功上傳其中一條側溝後先開啟檢視側溝頁面；關閉檢視頁面後回到本次新增清單，僅移除已成功上傳項目及其本機未上傳草稿，不影響其他項目，且不得呼叫後端刪除 API。
- AC-007：既有單條側溝新增／編輯、草稿恢復、照片保存及上傳、無法開蓋、虛擬點、檢視模式與主地圖控制項行為不回歸。
- AC-008：任一側溝送出失敗時，使用者確認既有失敗 Alert 後回到本次新增清單；該失敗項目與草稿保留，可繼續編輯或重送。
- AC-009：每張實際上傳至 `/v1/node/nodeImage` 的照片都是獨立 multipart 請求，並帶有該照片的 `captured_at`；無法取得原始時間時以裝置目前時間、沿用既有格式補入。
- AC-010：任何 `/v1/ditch/storeDitch` 節點 payload 均不包含 `captured_at`；既有照片是否需要重傳的判定不變。

## Constraints
- 需求文字優先於 Figma 範例的相衝突描述：Toolbar 採左側關閉／刪除、右側「＋新增」；建立時間顯示至秒；關閉 Alert 的文字與按鈕為本需求指定內容。
- Figma 節點 `2374:25786`／`2374:26810` 為視覺與元件階層參考，不得覆寫本需求的行為或資料保存規則。
- 清單中的一列代表一條側溝及其完整點位集合；它必須對應一筆獨立的 `GutterSessionDraft`。
- `captured_at` 的責任邊界固定為照片上傳 API，不得以改動既有照片重傳判定或照片時間格式達成此調整。

## Open Questions
- 無。空白、尚未有任何有效資料的新列不會列入未上傳草稿，也不會在關閉時建立空草稿；此為沿用既有草稿清理規則的可逆假設。
