# Fix Requirement

## 問題描述

目前 `AddGutterBottomSheet` 在送出前會先做資料/照片驗證。  
當某個照片欄位已經有可用的照片路徑，但該照片尚未取得 `img_id` 時，系統仍可能直接跳出「資料/照片不足」Alert，導致後續「一併補傳照片」流程無法執行。

這與預期行為不一致。

## 預期行為

送出前的照片判定應區分以下情況：

1. 照片欄位已有 `img_id`
   - 視為已完成，不需再次上傳。

2. 照片欄位沒有 `img_id`，但已有可用照片路徑
   - 視為可補傳狀態。
   - 應進入「一併補傳照片」流程，由系統逐張補傳並取得缺少的 `img_id`。
   - 不應在此時跳出「資料/照片不足」Alert。

3. 照片欄位沒有 `img_id`，且也沒有可用照片路徑
   - 視為缺少照片。
   - 允許由 Alert 提醒使用者補拍。

4. 照片欄位有照片路徑，但檔案實際不可讀、不可用
   - 視為缺少照片。
   - 不應勉強進入補傳流程，最後仍應由 Alert 提醒使用者補拍或修正照片狀態。

## Alert 行為要求

`資料/照片不足` Alert 僅應在以下情況出現：

1. 必要資料欄位不完整。
2. 必要照片欄位沒有可用照片路徑，且無法進入補傳流程。

以下情況不得被此 Alert 擋住：

1. 照片已有可用路徑，但尚未取得 `img_id`。
2. 可透過送出前補傳流程補齊 `img_id` 的照片。
3. 路徑存在但檔案不可用，且仍可被當成補傳中的有效照片。

## 修正範圍

本次修正應只調整送出前的判定邏輯與流程順序，不改變既有：

1. 單張照片上傳 API 結構
2. `PhotoSlotUploadCoordinator` 上傳機制
3. 草稿資料結構
4. `img_id` 回填結構

## 核心判定原則

資料驗證時：

- 應先判斷資料欄位是否完整。
- 對於照片欄位，應先判斷「是否有可用照片路徑」。
- 若有可用照片路徑但 `img_id` 尚未取得，應導向送出前一併補傳，不可直接視為照片不足。
- 若照片路徑存在但檔案不可用，應視為缺少照片，最後才進入 Alert。
