# Fix Requirement Timeout Test

## 測試目標

驗證 `storeDitch` 失敗時的兩條特殊流程：

- 網路逾時
- `409 Conflict` 的照片認領失敗

並確認這兩條流程都可透過測試接口觸發，而測試接口受 `ENABLE_GROUP_SIMULATION = true` 控制。

## 測試接口要求

### 顯示條件

1. `ENABLE_GROUP_SIMULATION = true`
2. 在新增或編輯側溝表單中長按 `送出` 按鈕

### 預期結果

1. 顯示測試選單
2. 測試選單提供至少兩個項目：
   - `模擬網路逾時`
   - `模擬照片認領失敗(409)`
3. `ENABLE_GROUP_SIMULATION = false` 時，不顯示任何測試選單

## 409 測試驗收

### 新增模式

前置條件：

1. 開啟新增側溝表單
2. 長按 `送出`
3. 選擇 `模擬照片認領失敗(409)`

預期結果：

1. 顯示標題 `照片認領失敗`
2. 顯示單一按鈕 `關閉`
3. 不顯示 `重傳` 或 `存入草稿`
4. 關閉後流程需等同於 `storeDitch timeout`

### 編輯模式

前置條件：

1. 開啟編輯側溝表單
2. 長按 `送出`
3. 選擇 `模擬照片認領失敗(409)`

預期結果：

1. 顯示與新增模式完全相同的 `照片認領失敗` 視窗
2. 僅有 `關閉` 按鈕
3. 關閉後流程與 `storeDitch timeout` 一致

## timeout 測試驗收

### 新增模式與編輯模式

前置條件：

1. 開啟表單
2. 長按 `送出`
3. 選擇 `模擬網路逾時`

預期結果：

1. 顯示原本既有的 `網路連線逾時` 視窗
2. 按下 `關閉` 後仍走原本的 timeout 收尾流程
3. 不應受到 409 測試功能影響

## 驗收重點

1. 測試接口必須受 `ENABLE_GROUP_SIMULATION` 控制
2. `409` 與 timeout 必須可從同一個測試入口切換
3. `409` 視窗必須只有單一 `關閉` 按鈕
4. `409` 關閉後收尾必須沿用 timeout 的 host 路徑
5. 不可修改原本上傳流程與草稿結構
