# Requirement

## Task Metadata

```yaml
task: TYG-XXX
type: feature

references:
  product: []
  design: []
  api: []
  assets: []

specification_versions:
  product-spec: ""
  design-spec: ""
  api-contract: ""
  reusable-assets: ""
```

## Background
- 1~3 行說明背景即可

## Goal
- 1~3 行說明要達成什麼

## Functional Requirements
- 用條列寫最必要的功能點

## Non-functional Requirements
- 沒有就寫 `無`

## Acceptance Criteria
- 用 `AC-001` 起編號，逐條寫可驗證結果

## Constraints
- 寫不可改的限制或前提；沒有就寫 `無`

## Specification Conflicts
- 規格之間或規格與 Task 的衝突；沒有就寫 `無`

## Open Questions
- 只列會影響實作判斷的問題；沒有就寫 `無`
